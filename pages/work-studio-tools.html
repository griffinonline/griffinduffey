the tooling behind the studio

MOMENT (formerly oratory) designer + builder 2026 internal tools, no public link

the problem

a studio of four or five people running ten to twelve client projects at once. in eighteen months the team had tried four project tools, and each one died the same way: it was a second place to type something that already lived in slack.

i was the project manager, so the mess landed on me. i'd rather build the fix than complain about it.

what i did

  • a project dashboard to replace coda. every project on one board by phase, timelines that push back on their own when a date slips, and phase templates for each package.
  • slack does the updating. a bot reads the client channels and writes short summaries into each project, so nobody has to fill in a status.
  • client intake. a form the client fills in, a review queue, an ai-written brief, and one click to create the project and its slack channels.
  • kept the data safe. when a departing developer's accounts would have taken the database and deploys with them, i moved both to accounts the studio owned and checked every row came across.
  • a handoff checklist. the steps every site ships with, including a check of everything that runs on a server and who owns it after we leave.

how it went

i wrote about 177 of the dashboard's 213 commits, and the studio ran its projects on it [check: for how long + how many projects].

the bigger lesson outlasted the tool: anything new has to work out its state from where the work already happens (slack, the repos, the calendar) instead of asking people to type it. that rule shaped what came next, including the delivery docs and intake for MOMENT's sprints.

working together

these were tools for my own teammates, so the test was simple: would people actually open it? i built around how the team already worked and changed it when they told me something was in the way.
